# Deploying the Report Transformer

Two things to know before you start.

**The repository must be PRIVATE.** `seed/` carries MASTER DATA CONFIRMED.xlsx
(every shop code, name and bond) and the 81 build scripts. Neither belongs on
the public internet.

**The disk is not optional.** The workbooks *are* the data — a month's earlier
days exist only inside them. A service without a disk comes up empty after
every deploy. `render.yaml` asks for a 5 GB disk on the Starter plan.

---

## 1. Put the code on GitHub

Create an **empty private repository** on github.com — no README, no
.gitignore, nothing. Call it `ksd-report-transformer`.

Then, in Terminal:

    cd ~/Downloads/Claude/"Report Transformer App"
    git remote add origin https://github.com/YOUR-USERNAME/ksd-report-transformer.git
    git push -u origin main

macOS asks you to sign in to GitHub the first time and remembers it after that.
The commit is already made; this only sends it.

## 2. Create the service on Render

1. **New +** → **Blueprint**.
2. Connect your GitHub account and pick `ksd-report-transformer`.
3. Render reads `render.yaml` and proposes: one web service, Starter plan,
   Singapore, a 5 GB disk at `/data`. **Apply.**

First build takes about five minutes — it installs LibreOffice, which the PDF
scripts need.

## 3. Set your password

Open the service URL. Because no account exists yet, the sign-in page offers
**"set your password"**. Use `abhaymearish@gmail.com`, at least 12 characters.
That page closes itself the moment an account exists — nobody else can use it.

## 4. Upload something and check

Raw Data Upload → Shop Sales - Cumulative → a period file. The reports fill in.
The disk keeps it across restarts and deploys.

---

## Adding someone else later

Render → the service → **Environment** → edit `KSD_ALLOWED_EMAILS` to
`abhaymearish@gmail.com,them@example.com`, save (the service restarts), then
they visit the URL. The first-run page is closed by then, so ask me to add the
account — or set `KSD_ALLOWED_EMAIL_DOMAINS` to a company domain instead.

## What is where

| | |
|---|---|
| `/data/workspace` | uploads, built workbooks, job history, password hashes |
| `seed/` | reference material copied to the disk on first boot, never overwritten |
| `KSD_SESSION_SECRET` | generated by Render, never in the repo |

## If a deploy fails

Render → **Logs**. Lines starting `[startup] PROBLEM:` name what is missing.
`script not found` means `seed/scripts/` did not make it into the image.
